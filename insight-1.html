Abstraction and reusability are the keys to a consumer’s heart

Within the classroom
CSCE 145 & 146: Algorithmic Design I & II
Beyond the classroom
Software engineering internship, Deutsche Bank
Concept
Object-oriented programming: abstraction & reusability

Abstraction and reusability are the keys to a consumer’s heart. If someone told me this while I was entering college four years ago, I would’ve said “Sure, reusability makes sense. I like to reuse the same phone charger every night. But what is abstraction?”.

Well, I would learn what abstraction is within my first semester at USC in CSCE145: Algorithmic Design I. This class was exciting. Coming into school to study Computer Science, I appreciated the opportunity to jump straight into computing focused classes unlike my friends from other schools. In this class, we were taught the fundamentals of object-oriented programming (OOP) in Java. This class was also further extended into the spring semester with CSCE146: Algorithmic Design II. In these classes, we were taught engineering best practices including writing code that is readable, maintainable, scalable and secure. Additionally, we were taught the 4 key pillars of OOP: abstraction, encapsulation, inheritance and polymorphism. I was asked about the 4 key pillars of OOP during internship interview at Deutsche Bank and ultimately used them throughout my internship.

CSCE145 and CSCE146 are a core reason I have developed the critical thinking and problem-solving skills that allow me to succeed today. My freshman year, AI was around but still performing to a low standard. Additionally, I took it upon myself to not use generative AI tools in these intro classes because without a strong foundation everything built on top of it would crumble. You may have noticed, I said reusability is one of the key features to a consumer’s heart. Yet that isn’t one of the best practices. So how does it fit in? Reusable code is what makes all the best practices possible. Code is readable when functionality is written once and reused consistently. Code is maintainable when code is reused, and you can refactor in one place to make improvements everywhere. Code is scalable when applications are containerized and able to be deployed universally, Code is secure when known best practices are reused. If vulnerabilities are found, a fix in one implementation cascades across its duplicate versions.


This is where abstraction enters the picture. Reusability solves the problem, “How can I use this again?” and “How can I reduce waste”. Abstraction solves the problem, “How can I get people to use my product without them actually needing to understand how the underlying technology works?”

I saw this extensively during my time at Deutsche Bank. While working on core software for the investment bank, I came in contact with an issue of handling tens of thousands of requests within a matter of seconds. The system was set up where our service could only connect to 10 endpoints at a time. When you are receiving thousands of requests a second, and each request taking 100 – 200ms to process. There was no way to serve these requests efficiently by using a 1:1 connection ratio. That is when we pivoted and decided to use batch processing. This allowed us to utilize the 10 connection endpoints more efficiently by batching hundreds of user requests into a single packet to be shared with the connection. This greatly improved our processing speed by well over 20x. So, you may be asking, “How does this relate to abstraction?”. Well truly its quite simple. The investment bankers using our pricing platform only care about their request going through and them being able to book trades and serve the clients properly. They don’t need to understand that their request was batched with hundreds of other bankers’ requests on the way to getting their trade completed. That’s the beauty of abstraction, as engineers we can provide world class experience without the user ever needing to know what is going on under the hood.


Overall, the introduction of engineering best practices and the pillars of OOP allow me to design high-quality code and create the most seamless experience for my clients.
